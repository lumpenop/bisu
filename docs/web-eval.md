# 웹 작업 평가 기록

비서가 브라우저로 하는 일(웹에서 대신 하기)을 어떻게 재고, 회차마다 무엇이 바뀌었는지 모아 둔 기록입니다.
가장 최근 기록이 맨 아래에 있습니다.

## 재는 방법

- **스크립트:** `engine/eval/web-tasks.mjs`
  ```
  OPENAI_API_KEY=dec://OPENAI_API_KEY GLM_API_KEY=dec://GLM_API_KEY dec-secret run -- \
    node engine/eval/web-tasks.mjs --set holdout2 --modes dec,ego,aside --repeat 2
  ```
  - `--set`: `speed`, `complex`, `hard`, `holdout`, `holdout2` 중 하나
  - `--modes`: 아래 네 방식 중 고를 수 있어요(쉼표로 여러 개)
  - 한 번 실행할 때마다 JSON 한 줄을 남겨요(과제, 방식, 초, 성공 여부, 답, GLM을 부른 횟수와 이유).
- **방식 네 가지:**
  - `dec`: 비서가 Dec을 직접 조작해요. Dec 빠른 모드는 꺼야 해요.
  - `ego`, `aside`: 비서가 ego lite와 Aside를 직접 조작해요.
  - `decfast`: Dec 빠른 모드가 혼자 판단해요(Decisions + GLM). 빠른 모드를 켜야 해요.
- **판단 모델:** 단계마다 Decisions가 고르고, GLM은 문제가 생겼을 때만 불러요.
- **사이트:** 모두 스크래핑 연습용이라 반복 실행해도 괜찮아요.
  - books.toscrape, quotes.toscrape
  - scrapethissite, webscraper.io 테스트 쇼핑몰, the-internet
  - web-scraping.dev, scrapingcourse, Oxylabs 샌드박스
- **원본 결과:** `engine/eval/results/<날짜>/*.jsonl`
- **홀드아웃:** 처음 보는 사이트의 과제를 코드 수정 없이 재는 거예요. 한 번 재고 그 실패를 고치면 그 세트는 더 이상 홀드아웃이 아니라서, 그다음 평가는 새 세트로 해요.

실패 원인은 모두 어디서나 생길 수 있는 버그였어요.
- **Dec(비서)·요청 만료:** 판단하는 사이 페이지가 바뀌면 Dec이 요청을 만료(STALE_REQUEST)시키는데, 다시 보지 않고 오류로 끝냈어요.

- **쪽 번호:** 이 사이트는 쪽 번호가 `?page=2`에만 있는데, Dec이 `?` 뒤를 빼고 넘겨서 쪽끼리 구별되지 않았어요. 「같은 페이지」 판정도 앞뒤 3줄만 봤어요.
- **ego 스크롤:** 이미 페이지 전체를 보고 있는데 스크롤만 반복했어요.
- **Aside:** 큰 페이지는 접근성 트리가 잘렸고, 표 행을 잘못 읽었어요.

모두 고쳤고(bisu `1be2695`, Dec `6bf7a69`), 이 세트로 다시 확인했어요. 이제는 본 세트라 평가 수치가 아니에요.
