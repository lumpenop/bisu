# 웹 작업 평가 기록

비서가 브라우저로 하는 일(웹에서 대신 하기)을 어떻게 재고, 회차마다 무엇이 바뀌었는지 모아 둔 기록입니다.
가장 최근 기록이 맨 아래에 있습니다.

## 재는 방법

- **스크립트:** `engine/eval/web-tasks.mjs`
  ```
  OPENAI_API_KEY=dec://OPENAI_API_KEY GLM_API_KEY=dec://GLM_API_KEY dec-secret run -- \
    node engine/eval/web-tasks.mjs --set holdout2 --modes dec,ego,aside --repeat 2
  ```
  - `--set`: `speed`, `complex`, `hard`, `holdout`, `holdout2` 중 하나
  - `--modes`: 아래 네 방식 중 고를 수 있어요(쉼표로 여러 개)
  - 한 번 실행할 때마다 JSON 한 줄을 남겨요(과제, 방식, 초, 성공 여부, 답, GLM을 부른 횟수와 이유).
- **방식 네 가지:**
  - `dec`: 비서가 Dec을 직접 조작해요. Dec 빠른 모드는 꺼야 해요.
  - `ego`, `aside`: 비서가 ego lite와 Aside를 직접 조작해요.
  - `decfast`: Dec 빠른 모드가 혼자 판단해요(Decisions + GLM). 빠른 모드를 켜야 해요.
- **판단 모델:** 단계마다 Decisions가 고르고, GLM은 문제가 생겼을 때만 불러요.
- **사이트:** 모두 스크래핑 연습용이라 반복 실행해도 괜찮아요.
  - books.toscrape, quotes.toscrape
  - scrapethissite, webscraper.io 테스트 쇼핑몰, the-internet
  - web-scraping.dev, scrapingcourse, Oxylabs 샌드박스
- **원본 결과:** `engine/eval/results/<날짜>/*.jsonl`
- **홀드아웃:** 처음 보는 사이트의 과제를 코드 수정 없이 재는 거예요. 한 번 재고 그 실패를 고치면 그 세트는 더 이상 홀드아웃이 아니라서, 그다음 평가는 새 세트로 해요.

## 1. 기본 속도 (books.toscrape, 2회씩)

과제는 세 가지예요.
- **간단:** 첫 페이지 책 가격
- **중간:** 카테고리 → 책 → 가격·재고
- **깊은 작업:** Mystery 2쪽 최고가 책의 제목·가격·재고·UPC

| 과제 | Dec | ego | Aside |
|---|---|---|---|
| 간단 | 1.4~1.6초 | 1.6~1.9초 | 2.3~2.8초 |
| 중간 | 3.1~4.3초 | 4.0~4.2초 | 4.2~4.3초 |

- **Dec 빠른 모드:** 간단 3.6~3.9초, 중간 4.5~4.7초, 깊은 작업 7.3~8.4초. 전에는 8.8~14.5초였고, 1.5초 답 확인 대기가 들어 있어요.
- **이 사이 바뀐 것:**
  - Dec이 같은 Mac의 비서에게 페이지 전체(후보·글)를 넘겨요.
  - Dec 분당 호출 한도에 맞춰 호출 수를 줄였어요.
  - 가격 최상급은 페이지에서 직접 읽어요.
  - 여러 항목을 묻는 답은 항목별로 Decisions에 물어요.
  - 목표에 이름이 나온 링크는 비교 단계 없이 바로 따라가요.

## 4. 홀드아웃 1 (10-29, 처음 보는 사이트, 코드 수정 없이 측정)

| 과제 | 사이트·내용 | Dec 빠른 모드 | ego | Dec(비서) | Aside |
|---|---|---|---|---|---|
| O1 | scrapethissite 250개국 중 Iceland 수도·인구 | 2/2 | 2/2 | 2/2 | 0/2 |
| O2 | 하키팀 「Boston」 검색 후 1993년 승수 | 2/2 | 2/2 | 2/2 | 0/2 |
| O3 | webscraper 노트북 117개 최고가(가격이 이름보다 먼저 나옴) | 2/2 | 0/2 | 1/2 | 1/2 |
| O4 | 태블릿 4쪽 전체 최고가 | 1/2 | 2/2 | 0/2 | 1/2 |
| O5 | the-internet 표, Due 최대 | 2/2 | 2/2 | 2/2 | 2/2 |
| O6 | 오스카 2015 최다 수상작(AJAX) | 2/2 | 0/2 | 0/2 | 2/2 |
| **합계** | | **92%** | 67% | 58% | 50% |

실패 원인은 모두 어디서나 생길 수 있는 버그였어요.
- **Dec(비서)·요청 만료:** 판단하는 사이 페이지가 바뀌면 Dec이 요청을 만료(STALE_REQUEST)시키는데, 다시 보지 않고 오류로 끝냈어요.
- **AJAX:** 클릭 뒤 같은 페이지에 표가 늦게 뜨는데 기다리지 않고 같은 클릭을 반복했어요. Dec은 이때 「기다리기」 후보를 주지 않았어요.
- **쪽 번호:** 이 사이트는 쪽 번호가 `?page=2`에만 있는데, Dec이 `?` 뒤를 빼고 넘겨서 쪽끼리 구별되지 않았어요. 「같은 페이지」 판정도 앞뒤 3줄만 봤어요.
- **ego 스크롤:** 이미 페이지 전체를 보고 있는데 스크롤만 반복했어요.
- **Aside:** 큰 페이지는 접근성 트리가 잘렸고, 표 행을 잘못 읽었어요.

모두 고쳤고(bisu `1be2695`, Dec `6bf7a69`), 이 세트로 다시 확인했어요. 이제는 본 세트라 평가 수치가 아니에요.

- **Aside 50%:** 실패 6건이 모두 같은 버그였어요. 선택 상자 항목이 `option "descending" value="desc"`처럼 속성까지 붙어 오는데 이 형식을 해석하지 못해 바로 오류가 났어요. 고친 뒤 확인용으로 다시 돌리니 P2·P3은 통과하고 P1은 실패했어요(`holdout2-aside-after-fix.jsonl`).
- **P1:** 가장 어려운 과제예요. 5쪽을 넘기며 통화 기호 없는 가격을 비교해야 해요.
  - Dec(비서)은 맞혔지만 느렸어요(28~102초).
  - ego는 「>」만 반복하다 멈췄어요.
  - Dec 빠른 모드는 한 번은 다른 상품의 가격을 붙였고, 한 번은 단계 한도에 걸렸어요.
- **Dec(비서) P6 1건:** 「유형(Type)」을 장르로 답했어요. 모델이 뜻을 헷갈린 경우예요.

### 범용성 판단

- **어디서나 통하는 수정(버그 수정):**
  - Dec 연결: 주소·쪽 번호·요청 만료·새 탭·실행 한도·http
  - 같은 이름 링크 구별, 늦게 뜨는 내용 기다리기, 쓸모없는 스크롤 멈추기
  - 앞 페이지 답으로 끝내지 않기, 메모 보강, Aside 해석 버그
- **특정 목표 유형에만 효과가 있는 것:** 가격 최상급 직접 고르기, 「최고가−최저가 차이」 계산, 「각각」 체크리스트. 애매하면 GLM으로 넘겨서 틀리게 만들지는 않아요.
- **결론:** 홀드아웃 2 기준으로 Dec(비서 직접) 92%, ego·Dec 빠른 모드 83%예요. 첫 홀드아웃(58%·67%·92%)보다 Dec과 ego가 좋아졌어요. 같은 사이트를 다시 재면 홀드아웃이 아니라서, 다음 평가도 새 사이트로 해야 해요.

## 남은 일

- **여러 쪽 비교:** P1처럼 여러 쪽을 넘기며 비교할 때 느리거나 막혀요. 쪽마다 메모하고 끝까지 간 뒤 고르는 흐름이 필요해요.
- **H2:** 여러 쪽짜리 카테고리마다 최고가를 찾아 연 뒤 비교하는 흐름이 없어요.
- **ego:** 「>」 같은 기호 쪽 이동 링크에서 같은 단계를 반복해요.
- **Dec 빠른 모드:** 3·4절에서 고친 항목(페이지 구분, 연 상품 페이지 비교 금지 등)이 아직 일부 없어요.
